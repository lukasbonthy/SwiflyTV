# Pengu 4K Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the configured addon's verified Pengu 4K MP4 available to SwiflyTV.

**Architecture:** Extend the existing exact provider registry. Retain the verifier, opaque proxy, HEVC header compatibility and on-demand search.

**Tech Stack:** Node.js, existing Stremio bridge, node:test, FFmpeg for live validation.

**Spec:** `docs/superpowers/specs/2026-10-30-pengu-4k-design.md`

## Global Constraints

- No provider credentials or signed URLs in Git.
- Reject unsupported MKV, unknown provider identities and unverifiable links.
- Preserve explicit provider headers and current public-address protections.
- Normal playback retains its fast path.

## Review Focus

- Missing source User-Agent: real media verification must succeed and retain the header for playback.
- Explicit headers: preserve their values rather than silently replacing them.
- Unknown or misleading provider names: never accept arbitrary addon results.
- A codec mentioned in a title: use only explicit codec tokens and retain verification.
- Configuration absent: do not advertise Pengu as installed or selected.
