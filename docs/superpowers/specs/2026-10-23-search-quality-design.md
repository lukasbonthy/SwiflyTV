# Search quality and site consistency

The user asks for a substantial AI quality pass, a search bar and notification HUD that match the existing site, fewer AI effects, and a more useful site loader. The existing compact dark shell and its shared soft glass are the visual reference. Keep the normal aurora and understated interaction cues; remove the feature-specific neon, large lifts, sweeps and orbital decoration from AI.

AI work uses the existing free local model and authenticated catalog APIs. Diagnose intent parsing, retrieval and ranking separately with a diverse labeled query set, run genuine model inference, and record before/after results. Respect exclusions, dates, format, runtime and language when supplied. Exact or misspelled titles, plot descriptions and requests similar to a title need different retrieval paths. Preserve the user's additional preferences in similar-title ranking, avoid treating inferred topics as mandatory genres, and return useful grounded results with an honest explanation. Avoid invented titles and random fallback filler. Do not add a paid service or large generative model download.

Search and notifications reuse existing navigation materials and compact typography. Keep live results, keyboard navigation, All/Unread controls, unread counts, focus retention and existing privacy boundaries. AI should show concise useful state, interpreted filters and result reasons rather than decoration.

The site loader must communicate its destination, stay tied to actual document/critical-content readiness, and keep navigation accessible. Use destination-specific placeholders and an indeterminate activity indicator, not a fabricated completion percentage. Avoid flashing on fast navigation or waiting on optional assets. Honor reduced motion and Xbox/TV. Retain canceled-navigation, history, download/new-tab and timeout safeguards. A backward-compatible `SwiflySiteLoading.hold(message?: string)` returns an idempotent release function; connect and audiobook initial fetches release it in finally. AI inference has its own inline progress and never blocks the entire site.

Approaches considered: a heavier generative browser model adds substantial startup cost; a style-only patch leaves bad recommendations untouched. Chosen implementation is to repair intent/retrieval/ranking using the existing model, validate real inference, and simplify shared feature surfaces. This is an implementation choice made within the user's request.
