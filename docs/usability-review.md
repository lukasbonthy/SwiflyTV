# SwiflyTV usability review — 27 October 2026

The review covered every user-facing route family in the design, including aliases, the embedded watchroom, invalid routes and the standalone stream player. Changes target unclear labels, missing next actions and broken behavior. Existing player, social, Study, profile and AI controls remain available. A repeated page-guide banner was not added: the existing pages already have suitable headers, and direct labels and actions address the problems with less clutter.

Existing tests cover the unchanged AI controls, query/Back behavior, profile preferences, Trakt, Study playback/tasks/timers/room lifecycle, and authenticated message flows.

The browser script `.superpowers/sdd/2026-10-27-recovery-studio/review-routes.cjs` loaded the actual server and reviewed **49 routes/aliases at 320 × 844 and 1440 × 1000**, for **98 served page renders**. It retained per-route headings, status, overflow metrics, form-label findings, asset failures and page errors in `page-review/route-review.json`. It captured 20 full-page screenshots, including Settings, empty List, Friends, Study, Welcome, AI search, Genres, Profiles, Favorites and the utility player at both widths. Phone/desktop Settings and phone empty List/Friends were visually inspected. Real Clear filters restored the saved card and focused library search; the Settings Studio trigger opened the actual Studio dialog.

The baseline render pass had **no document-level horizontal overflow and no failed same-origin assets**. The only fatal page error was the embedded watchroom’s missing script terminator, reproduced at both widths. The only unnamed form controls found were the three fake genre selects and the six embedded-room fields described above. Controls outside the viewport inside intentional horizontal shelves/tab bars are recorded separately and are not document overflow.

After the root server fixes, `.superpowers/sdd/2026-10-27-recovery-studio/review-integrated-routes.cjs` re-rendered **18 affected routes at both widths (36 additional renders)** and captured 36 screenshots in `page-review-integrated`. Every route returned HTTP 200, with **0 fatal page errors, 0 failed same-origin assets, 0 document overflow and 0 unnamed main-form controls**. This includes the real original-language query, Favorites, Account backup UI, the previously broken embedded watchroom, profile management, Settings, Kids, auth and the URL-form utility player. Real Clear filters and Settings → Studio passed again. The integrated phone Genres and utility-player screenshots were visually inspected.

The pass uses real same-origin scripts/styles, browser storage and the actual guest-account endpoint. TMDB metadata and external artwork are fixed typed fixtures. Player source and audiobook requests use deterministic empty fixtures to inspect recovery/layout. It does not validate production persistence, live catalog accuracy, provider playback, model downloads, real cameras/microphones, peer calls or TURN connectivity. After integration, the affected server routes were rechecked; the root implementation runs the full required suite before claiming whole-branch completion.

## Exact integration and follow-up notes

- Mount `/liked` with `data-library-page data-library-default-tab="liked"`; `library-page.js` preserves query overrides, explicit Saved selection and the existing bulk-clear feature.
- Backups are linked only to the actual root-owned `/account#account-data` module, with no dead Import button in Settings or the library.
- The integrated language form uses TMDB’s original-language filter, not the metadata-translation `language` parameter. The official Discover references were checked: <https://developer.themoviedb.org/reference/discover-movie> and <https://developer.themoviedb.org/reference/discover-tv>. Its labeled controls wrap into two columns at 320px using the existing form tokens.
- Originally, any catalog `__error` entered `setupNeededPage`, which always instructed viewers to configure a TMDB key and exposed deployment instructions. Root replaced it with a viewer-facing unavailable state, Try again and Open My List. Transient errors no longer imply that the viewer must configure a server.
- The global footer’s Clear watchlist remains available. Root fixed its persistence failure: the compatibility mirror rolls back if profile storage fails, success toasts require a durable local write, and signed-in clearing awaits real account upload. A regression test executes the actual shared inline handler with a quota failure.
